Build procedural setups in Houdini with AI

By Jethin · 1 October 2026 · 2 min read

Houdini is built around node networks, and every node, parameter and connection can be created from Python through the hou module. That makes it a good match for AI: the AI writes the network, Houdini shows the result, and you steer it with plain language. This guide walks through connecting Houdini to Homebox and building a small procedural setup.

Connect Houdini

  1. Turn on Houdini in HomeboxOpen Apps → Houdini and switch on Let AI control Houdini.
  2. Start the bridgeIn Houdini, open Windows → Python Shell, paste the setup line shown in Homebox and press Enter. The shell prints Homebox: Houdini is listening on port 7011.
  3. TestClick Test connection in Homebox. To skip the paste next time, turn on Start automatically, which adds a marked block to your 456.py startup script.

A first task: scattered rocks

Start a new chat, click the Homebox button and try:

In Houdini, under /obj make a geo node called rocks_setup.
Inside it: a grid 20 x 20, scatter 200 points on it, and copy a
small sphere (radius 0.15) onto the points with random scale
between 0.5 and 1.5. Name every node clearly, lay out the network,
and set the display flag on the final node. Report the node paths.

The AI builds this in a few steps. Each step's Python appears in Homebox for approval, so you can read exactly which nodes it creates. A typical step looks like:

geo = hou.node('/obj').createNode('geo', 'rocks_setup')
grid = geo.createNode('grid', 'ground')
grid.parm('sizex').set(20)
grid.parm('sizey').set(20)
scatter = geo.createNode('scatter', 'rock_points')
scatter.setInput(0, grid)
geo.layoutChildren()
print(scatter.path())

Why one step at a time works best

Each approved step runs inside a single Houdini undo group, so Ctrl+Z in Houdini removes the whole step. Small steps mean small undos. They also let the AI read back results: after creating the scatter, it can print the point count and adjust before moving on.

Giving feedback

The AI can't see your viewport, but it can read numbers. Useful feedback is concrete:

  • "The rocks are floating. Make sure the copies sit on the grid."
  • "Too uniform. Add a random rotation around Y."
  • "Print the bounding box of the final node so we can check its size."

Ask it to expose important values as parameters on the geo node ("add a spare parameter for rock count"), and you can then tweak the setup yourself without the AI.

Going further

  • Attribute wrangles: the AI can write VEX into an Attribute Wrangle's snippet parameter, for example to colour points by height.
  • Simulations: it can set up simple RBD or Vellum networks, but start with low resolution and ask for one stage at a time.
  • Saving: ask it to save the hip file into the sandbox, for example hou.hipFile.save(SANDBOX + '/rocks.hip').

Troubleshooting

  • "Houdini is not listening": paste the setup line again, or turn on Start automatically and reopen a scene.
  • "no Qt found": the bridge needs Houdini's normal window. It doesn't run in hython or a terminal.
  • A node type isn't found: node type names change between Houdini versions. Ask the AI to list available types with hou.sopNodeTypeCategory().nodeTypes() first.
