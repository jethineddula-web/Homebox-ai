How to write tasks AI can finish on its own

By Jethin · 30 September 2026 · 3 min read

With Homebox, the AI doesn't just answer. It works through a task in rounds: it acts, reads the results and decides what to do next. Some tasks sail through to DONE. Others stall, loop or wander. Most of the difference is in how the task is written.

1. Describe the outcome, not the steps

"Write a Python script" leaves the AI guessing. "A script rename.py that renames every photo in photos/ to its date taken, like 2024-05-01_001.jpg" tells it when it's finished. A clear finish line is what lets it stop by itself.

2. Name files and places

Say where things go: "put styles in css/site.css", "the Maya group should be called robot_grp". Names make it easy for you to check the result, and for the AI to find its own work in later rounds.

3. Give constraints up front

  • Tools: "plain HTML and CSS, no frameworks", "use only the Python standard library".
  • Scope: "don't touch files outside src/", "keep the existing layout".
  • Style: "comments in English, short functions".

Constraints stated at the start cost nothing. Corrections after twenty files cost a lot.

4. Ask it to check its own work

AI models rarely verify unless asked. End with a check: "after writing, read the files back and make sure every page links to the others", or in 3D, "after each part, print its bounding box so we can see it lines up". With commands enabled, "run the tests and fix failures before saying DONE" is very effective.

5. Break big jobs into stages

For anything larger than an afternoon's work, ask for a plan first: "List the files you'll create and what each does. Don't write anything yet." Approve or adjust the plan, then say "Build stage 1." Small stages keep each round short and make mistakes easy to undo.

6. Tell it what it can't see

The AI only sees text. It can't see your screen, a 3D viewport or a rendered web page. Describe problems concretely: "the logo overlaps the menu on narrow screens", "the left arm is 20% longer than the right".

7. Keep permissions tight

Turn on only what the task needs. A website needs file changes but not commands. A Blender scene needs Blender, not Excel. Fewer tools means fewer surprises, and the AI picks the right tool faster.

A template you can reuse

Goal: [what should exist when you're done]
Files/places: [where things go, what they're called]
Rules: [tools allowed, things not to change]
Check: [how to verify before saying DONE]
Work in small steps and stop when the goal is met.

Paste this into the Homebox New task box, fill in the brackets and press Start task.

Example: before and after

Before: "Make me a website." The AI has to guess everything, so it makes a generic page, stops early, and asks what you want.

After: "Goal: a one-page site for my photography, with a gallery of the images in photos/, a short About section and a contact email link. Files: index.html and style.css. Rules: plain HTML and CSS, works when opened directly. Check: read both files back and make sure every image path exists. Work in small steps and stop when the goal is met."

The second version takes a minute longer to write and usually saves many rounds of back-and-forth.
